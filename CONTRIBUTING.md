# Contributing to Deekshith B's Portfolio

Thank you for your interest in contributing to my portfolio project! This document provides guidelines and information for contributors.

## 🚀 Getting Started

### Prerequisites
- Node.js 18+ 
- Bun (recommended) or npm/yarn
- Git
- Basic knowledge of React, TypeScript, and Tailwind CSS

### Development Setup

1. **Fork the repository**
   ```bash
   git clone https://github.com/[your-username]/portfolio.git
   cd portfolio
   ```

2. **Install dependencies**
   ```bash
   bun install
   ```

3. **Start development server**
   ```bash
   bun run dev
   ```

4. **Create a feature branch**
   ```bash
   git checkout -b feature/your-feature-name
   ```

## 🎯 Contribution Guidelines

### Types of Contributions Welcome

- 🐛 **Bug Fixes** - Fix issues with existing functionality
- ⚡ **Performance Improvements** - Optimize loading times and performance
- 🎨 **UI/UX Enhancements** - Improve design and user experience
- 📱 **Responsive Design** - Better mobile and tablet support
- ♿ **Accessibility** - Improve accessibility features
- 📝 **Documentation** - Improve README or add documentation
- 🧪 **Testing** - Add or improve tests

### Code Style & Standards

- **TypeScript** - All new code should be written in TypeScript
- **ESLint** - Follow the existing ESLint configuration
- **Prettier** - Code should be formatted with Prettier
- **Component Structure** - Follow the existing component patterns
- **Naming Conventions** - Use descriptive, camelCase naming

### Commit Message Format

```
type(scope): description

Examples:
feat(ui): add dark theme toggle
fix(contact): resolve form validation issue
docs(readme): update installation instructions
perf(images): optimize image loading
```

### Pull Request Process

1. **Create a descriptive PR title**
2. **Fill out the PR template** (if available)
3. **Include screenshots** for UI changes
4. **Test your changes** thoroughly
5. **Update documentation** if needed
6. **Ensure all checks pass**

## 🧪 Testing

Before submitting a PR, please ensure:

- [ ] The project builds without errors (`bun run build`)
- [ ] All existing functionality works as expected
- [ ] New features are tested manually
- [ ] Responsive design works on different screen sizes
- [ ] Accessibility standards are maintained

## 📝 Reporting Issues

When reporting issues, please include:

- **Clear description** of the problem
- **Steps to reproduce** the issue
- **Expected vs actual behavior**
- **Browser and device information**
- **Screenshots** if applicable

## 💡 Suggesting Features

For feature suggestions:

- **Check existing issues** to avoid duplicates
- **Provide clear use cases** for the feature
- **Consider the scope** - features should align with portfolio goals
- **Discuss before implementing** - open an issue first

## 🏷️ Labels

- `bug` - Something isn't working
- `enhancement` - New feature or request
- `documentation` - Improvements to documentation
- `good first issue` - Good for newcomers
- `help wanted` - Extra attention is needed
- `performance` - Performance related improvements
- `accessibility` - Accessibility improvements
